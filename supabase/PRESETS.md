# Sensitivity Presets V1

- Guest source: `xensi-player-profile.presets` in localStorage. The existing nickname/avatar document is retained. The first read migrates non-UUID or duplicate IDs, normalizes the old `games` format, adds `presetStorageVersion: 1`, and keeps the original document in `xensi-player-profile:pre-presets-v1`. Unknown fields are retained during migration. Malformed JSON is not overwritten. Old training/session snapshots remain historical snapshots; their old IDs are not rewritten.
- Account source: `public.sensitivity_presets`. Local cache: `xensi-presets:user:<userId>:v1`. The cache is never used as guest data or sent back automatically. Fetch wins; there is no offline mutation queue. Account changes discard visible state and ignore late responses. Compound writes also verify `expected_user_id` against `auth.uid()`.
- UI uses `PresetRepository` through `usePresetState` / `usePlayerProfile`. Components do not query Supabase. Home, game pickers, training, conversion, profile editing and Finder saving use this shared source. Session drafts remain separate; manual edits do not mutate saved presets.
- Import is always offered after cloud fetch, including for an empty/new account. Nothing uploads before consent. Dismissal uses account-specific sessionStorage and resets on logout. The profile's import button can reopen the offer.
- Import is transactional and UUID-idempotent. A matching UUID preserves existing cloud values; different UUIDs preserve both presets, even with identical settings. UUID collisions with another account fail the whole import. Guest originals are retained. Account-specific receipts in `xensi-presets:imported:<userId>:v1` are written only after every uploaded UUID is confirmed in the response. Receipt failure can be retried safely. Changed guest data can be offered again, but does not overwrite a matching cloud UUID.
- At most one primary across all games, locally and in the account. Cloud primary wins on import. If there is no cloud primary, the guest primary is adopted. Partial unique index enforces the invariant; save/import/setPrimary RPCs use one transaction and an account advisory lock, run as SECURITY INVOKER, and respect RLS. Removing or unchecking a primary can leave none; game selection still falls back to a saved preset. Legacy documents retain their first explicit primary, or their first preset if none was marked.
- Cloud creation/update timestamps come from Postgres; the existing `xensi_set_updated_at()` trigger is reused. `cm/360` is not stored; the existing conversion engine remains authoritative. SQL checks enforce positive integer DPI, finite positive sensitivity and nonempty game ID. Frontend normalization uses each game's existing input model; there is no global arbitrary sensitivity range.
- Failed writes retain the previous UI/cache state and show localized errors. Retry by repeating the operation; refresh fetches cloud again. No optimistic cloud writes, realtime or background synchronization.

## Verification

`supabase/tests/sensitivity_presets.sql` checks own CRUD, cross-account denial, anon denial, owner reassignment, UUID conflict/retry, primary conflict/adoption, session mismatch, timestamps and cascade. It creates temporary fixture users inside a transaction and rolls everything back. This tests database authorization, not the Supabase Auth signup/email flow.

`npm run test` includes repository tests for migration, cache isolation, loading, failures, races and shared-cloud fetching from two instances. `npx playwright test --config playwright.presets.config.ts` runs desktop/mobile guest-login-import and account CRUD using intercepted Supabase responses with an isolated fake-key dev server. These are application integration tests, not real remote Auth or physical-device tests. Existing guest/Auth coverage: `npx playwright test tests/preset-flow.spec.ts tests/auth.spec.ts`.

Applied to project `zbdznwubrrkxuraispvr`: `20261004004933_create_sensitivity_presets.sql`. Remote inspection confirmed four ownership policies, authenticated-only CRUD grants, the FK/cascade, updated-at trigger and both secondary indexes. Database fixtures passed and were rolled back; the table contained zero rows after testing.

Security Advisor: no new preset findings. Existing nickname SECURITY DEFINER warnings ([anon](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)) and [disabled leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) remain outside this migration. Performance Advisor: no findings.
